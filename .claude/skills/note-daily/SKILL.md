# 毎朝の note 下書き（5アカウント）

公開は社長が note の画面で行う。このスキルは下書き保存で止める。

## 全体
1. `note/common.md`（共通ルール・アカウント一覧）と `note/templates.md`（型）を読む。
2. 今日の日付と曜日を日本時間で確認する（`TZ=Asia/Tokyo date`）。
3. 対象アカウント（指定がなければ一覧の5つすべて）について、下の「1アカウントの手順」を1つずつ行う。1つが失敗しても次へ進む。
4. 全部終わったら、まとめてコミットして今いるブランチに push する。
5. 最後に報告する。

アカウント間で題材・書き出し・締め方が重ならないよう、書く前に他アカウントの今日の記事を確認する。

## 1アカウントの手順（`<a>` = フォルダ名）

1. **準備**：`note/accounts/<a>/settings.md` と `log.md` を読む。
2. **材料**：`note/accounts/<a>/inbox/` のメモ（`used/` と `.gitkeep` を除く）から、いちばん古い1件を使う。メモがなければ common.md の「メモがない日」のルールに従う。
3. **型を決める**：settings.md の曜日表に従う。検証型の日に実測値のメモがなければ、表の注記どおりに切り替える。log.md の直近7件と題材がかぶらないようにする。
4. **書く**：writer の手順（`.claude/agents/writer.md`）で、settings.md の読者・トーン・注意点に合わせて書く。時事考察型はニュースを検索し、開いて確認したページだけを出典にする。
5. **推敲**：`stop-slop` スキル（`.claude/skills/stop-slop/SKILL.md`）で直す。日本語では次も確認する。
   - 一行だけの段落が3つ以上続いていない
   - 太字の決めゼリフが2つ以下
   - 「〜なのだと思います」「〜することが大切です」「いかがでしたか」がない
   - 締めの一文が、log.md の過去記事や他アカウントの今日の記事と同じ形になっていない
   - 5項目で採点して35点未満なら書き直す
6. **保存**：`note/accounts/<a>/drafts/YYYY-MM-DD-<短い英数字の題>.md`。1行目 `# タイトル`、最後の行 `ハッシュタグ: #a #b #c`。
7. **確認**：`python3 scripts/note_draft.py --account <a> <ファイル> --dry-run` で変換エラーがないか見る。
8. **note に下書き保存**：`python3 scripts/note_draft.py --account <a> <ファイル>`。シークレット未登録のエラーなら「未設定」として飛ばす。それ以外の失敗は再試行1回まで。公開系のAPIは呼ばない。
9. **記録**：使ったメモを `note/accounts/<a>/inbox/used/` に `git mv` する。`log.md` の表の先頭に1行追加する（note保存は「済」「失敗」「未設定」）。

## 報告（最後のメッセージ。スマホの通知に出る）
- 1行目：「note下書き 5本中◯本を保存しました」
- アカウントごとに1行：ジャンル／タイトル／型／保存結果（済なら編集画面URL、失敗なら理由）
- 公開前に社長が確認すべき点（事実、数字、表現。美容は薬機法に触れそうな表現）
- メモがなかったアカウント（「◯◯の inbox にメモがあると体験記事になります」）
