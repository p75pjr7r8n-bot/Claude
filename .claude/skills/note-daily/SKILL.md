# 毎朝の note 下書き

公開は社長が note の画面で行う。このスキルは下書き保存で止める。

## 手順

1. **準備**：`note/settings.md`、`note/templates.md`、`note/log.md` を読む。今日の日付と曜日を日本時間で確認する（`TZ=Asia/Tokyo date`）。
2. **材料**：`note/inbox/` のメモ（`README.md` と `used/` を除く）を古い順に見る。いちばん古い1件を使う。メモがなければ、settings.md の「メモがない日」のルールに従う。
3. **型を決める**：settings.md の曜日表に従う。検証型の日に実測値のメモがなければ、エッセイ型か時事考察型に切り替える。log.md の直近7件と題材がかぶらないようにする。
4. **書く**：writer の手順（`.claude/agents/writer.md`）で書く。時事考察型はニュースを検索し、開いて確認したページだけを出典にする。
5. **推敲**：`stop-slop` スキル（`.claude/skills/stop-slop/SKILL.md`）を読んで直す。日本語では次も確認する。
   - 一行だけの段落が3つ以上続いていない
   - 太字の決めゼリフが2つ以下
   - 「〜なのだと思います」「〜することが大切です」「いかがでしたか」がない
   - 締めの一文が、log.md にある過去記事と同じ形になっていない
   - 5項目で採点して35点未満なら書き直す
6. **保存**：`note/drafts/YYYY-MM-DD-<短い英数字の題>.md` に保存する。1行目 `# タイトル`、最後の行 `ハッシュタグ: #a #b #c`。
7. **確認**：`python3 scripts/note_draft.py <ファイル> --dry-run` で変換エラーがないか見る。
8. **note に下書き保存**：`python3 scripts/note_draft.py <ファイル>`。失敗しても記事ファイルは残し、エラー内容を最後の報告に書く。再試行は1回まで。公開系のAPIは呼ばない。
9. **記録**：使ったメモを `note/inbox/used/` に `git mv` する。`note/log.md` の表の先頭に1行追加する（note保存は「済」か「失敗」）。
10. **push**：コミットして、今いるブランチに push する。
11. **報告**（最後のメッセージ。スマホの通知に出る）：
    - 1行目：「note下書きを保存しました：<タイトル>」または「記事は作成、note保存は失敗：<理由>」
    - 型、文字数、使ったメモ
    - 編集画面のURL
    - 公開前に社長が確認すべき点（事実、数字、表現）
